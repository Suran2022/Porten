# Porten 移动端 · 瓶颈方案文档

> 本文档记录移动端开发过程中遇到的构建 / 兼容性瓶颈及最终解决方案，按时间顺序追加。
> 规范依据：项目开发规范第 3 条（每次修复或解决瓶颈问题都需在本文档追加）。

---

## 瓶颈 1：Gradle init 脚本损坏导致所有构建初始化失败

- **时间**：2026-10（工程骨架搭建期）
- **现象**：任何 Gradle 命令均失败，报 `maven { url https://... }` 语法错误。
- **根因**：沙盒预置的 `/root/.gradle/init.gradle` 内容损坏（缺赋值符号、`mavelCentral()` 拼写错误）；`init.d/maven-mirror.gradle` 镜像脚本与工程 settings 仓库策略冲突。
- **方案**：备份并移除损坏脚本；仓库策略统一收敛到工程 `settings.gradle.kts` 声明（官方仓库直连可达，避免镜像同步延迟引发假失败）。

## 瓶颈 2：AGP 9.1.0 与 Flutter 3.47.7 的双向兼容缺口（本工程最核心瓶颈）

- **时间**：2026-10（工程骨架搭建期）
- **现象**（按尝试顺序）：
  1. `android.newDsl=false`（Flutter 模板默认）：pub 插件 `shared_preferences_android` 的 Kotlin DSL 脚本报 `Unresolved reference 'compileSdkVersion'`；
  2. `android.newDsl=true`（AGP 9 默认）：Flutter Gradle 插件内部 `getLegacyAndroidExtension` 返回 null，抛 `NullPointerException`（该插件仍依赖 AGP 9 已移除的 legacy `BaseExtension`）。
- **根因**：Flutter 3.47.7（发布仅 2 天）自身处于过渡态——其 Gradle 插件运行时需要 legacy DSL，而其 pub 插件生态构建脚本已采用 AGP 9 内置 Kotlin 语法，两者互斥，无法在同一 properties 配置下共存。
- **决策**：向项目所有者确认后，工具链降级至成熟稳定组合，同时**保持 compileSdk=36 / targetSdk=36 不变**（新机型适配由 compileSdk/targetSdk 决定，与 AGP 大版本无关），minSdk 维持 24（Flutter 硬性下界）。
- **最终版本矩阵**：

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Gradle | 8.14.3（wrapper 经腾讯镜像分发） | 满足 Flutter 校验下界 8.14.0 |
| AGP | 8.13.1 | Flutter 校验下界（≥8.11.1）之上的成熟版 |
| Kotlin | 2.2.21 | 与 Gradle 内嵌 Kotlin 编译器同版，零 metadata 兼容问题 |
| compileSdk / targetSdk | 36 | Android 16，当前最新正式 SDK |
| minSdk | 24 | Flutter 3.47 硬性下界 |

- **附**：降级 AGP 的连带适配——`CommonExtension` 恢复 6 泛型参数（约定插件改为接收 `ApplicationExtension` / `LibraryExtension` 具体子类型委托公共配置）；Compose 编译器恢复由 `org.jetbrains.kotlin.plugin.compose`（KGP）提供。

## 瓶颈 3：build-logic 约定插件「全量成员 unresolved」

- **时间**：2026-10
- **现象**：build-logic 编译时，AGP / KGP 所有类的成员报 unresolved（`getDefaultConfig`、`configureEach` 等），但 import 正常。
- **根因（两个叠加）**：
  1. `VersionCatalogsExtension` 的 import 包名写错（正确为 `org.gradle.api.artifacts`）；
  2. Kotlin 中不能以方法调用形式访问 Java bean getter——`getDefaultConfig()` 必须写成属性 `defaultConfig`（Groovy 习惯迁移到 Kotlin 的典型坑）。
- **方案**：修正 import；`AndroidConvention.kt` 全部改为 Kotlin 属性语法（`extension.defaultConfig`、`extension.compileOptions`、`extension.packaging.resources` 等）；`versionCatalog.versionOf` 提为 internal 供各约定插件复用。

## 瓶颈 4：AGP 9 移除的旧全局开关

- **时间**：2026-10
- **现象**：`android.defaults.buildfeatures.buildconfig=true` 触发「removed in version 9.0」错误；flavor 使用 resValue 报「custom resource values, but the feature is disabled」。
- **方案**：删除全局开关，改为模块级显式开启——`:app` 约定插件开 `buildFeatures.buildConfig`，`app/build.gradle.kts` 开 `buildFeatures.resValues`。

---

## 瓶颈 5：仓库模式导致子工程依赖解析失败（aapt2 / kotlin-stdlib 找不到）

- **时间**：2026-10（首次完整构建期）
- **现象**：`PREFER_PROJECT` 模式下，`:core:*` 等子工程解析依赖时只搜索 Flutter 仓库（storage.googleapis.com），`com.android.tools.build:aapt2` 与 `kotlin-stdlib` 报 Could not find。
- **根因**：Flutter 插件向每个子工程注入 project 级 Maven 仓库，`PREFER_PROJECT` 语义是「项目声明了仓库就忽略 settings 仓库」，导致统一仓库声明被架空。
- **方案**：`repositoriesMode.set(RepositoriesMode.PREFER_SETTINGS)`——统一仓库（google / mavenCentral / flutter 官方产物仓库）全部收敛在 settings 声明，忽略插件注入的仓库（其所需 `download.flutter.io` 已在 settings 显式声明）。

## 瓶颈 6：pub 插件子工程 `flutter.compileSdkVersion` unresolved

- **时间**：2026-10
- **现象**：`shared_preferences_android` 构建脚本报 `Unresolved reference 'compileSdkVersion'`（注意 `flutter` 本身未报错）。
- **根因**：pub 插件脚本通过 `flutter.compileSdkVersion` 访问 `FlutterExtension`，该属性的 Kotlin DSL accessor 依赖根工程 buildscript classpath 中存在 Flutter 插件类型。
- **方案**：根 `build.gradle.kts` 补 `id("dev.flutter.flutter-gradle-plugin") apply false`（仅注入 classpath，不在根工程应用）。

## 瓶颈 7：androidx 最新版要求 compileSdk 37（尚未正式发布）

- **时间**：2026-10
- **现象**：AAR 元数据校验报 33 项「requires compileSdk 37 or later」（compose 1.12 / lifecycle 2.11 / navigation 2.10 / core 1.19 / okhttp 5.5 等）。
- **根因**：这些依赖是为下一代 SDK（37）预编译的预览线；而 SDK 37 平台尚未在 sdkmanager 提供（当前最新为 36 / Android 16）。
- **方案**：全量回退到「要求 ≤ 36」的最新稳定版（见 `gradle/libs.versions.toml` 注释）：compose BOM 2025.06.01、lifecycle 2.9.1、navigation 2.9.5、core 1.17.0、okhttp 4.12.0 等；SDK 37 正式发布后统一上探。

## 瓶颈 8：沙盒弱网导致依赖下载与 wrapper 校验挂起

- **时间**：2026-10
- **现象**：`services.gradle.org` wrapper 校验超时；`dl.google.com` 下载 aapt2 等大文件长时间无进展；曾出现一次 daemon 无故消失。
- **方案**：
  1. Gradle 分发包经腾讯镜像（`mirrors.cloud.tencent.com/gradle`）分发，写入 `gradle-wrapper.properties`；
  2. `gradle.properties` 追加 HTTP 超时与重试参数（`org.gradle.internal.http.socketTimeout=180000` 等）；
  3. 清理损坏的 init 脚本，消除无效镜像重定向。

---

## 瓶颈 9：Kotlin 版本与 Gradle 内嵌编译器的 metadata 兼容

- **时间**：2026-10
- **现象**：Kotlin 2.4.x 作为 KGP 时，build-logic（由 Gradle 内嵌 Kotlin 2.2.21 编译）出现全量 unresolved。
- **根因**：Kotlin 编译器最多读取超前一个 minor 的类文件 metadata（2.2 只能读 2.3，读不了 2.4）。
- **方案**：Kotlin 定格 2.2.21（与内嵌编译器完全同版，彻底消除该类问题；该约束已写入 toml 注释，防止后续误升）。

## 瓶颈 10：认证流程页第一轮还原偏差返工（图标/开屏/协议文案）

- **时间**：2026-10-11
- **现象**：第一轮认证页使用 Material Icons 近似 lucide 图标、开屏页自行设计（未对齐 SplashScreen.tsx）、协议文案为自写占位。
- **根因**：未严格逐文件研读 Web 端对应组件即编码，违反「100% 还原、禁止近似」硬性规范。
- **方案**：
  1. 图标：新增 `core/components/porten_icons.dart`，lucide 官方 SVG path（HelpCircle/Lock/MoreHorizontal/UserPlus/LogIn/Mail/Phone/User/Check）经 `path_parsing`（与 flutter_svg 同源解析器，`svg_path.dart`）在 CustomPainter 中逐条重建，strokeWidth 1.8 圆头圆角；BackIcon 使用 Web 端 1024 viewBox 实心箭头 path。
  2. 开屏：完整复刻 SplashScreen.tsx —— 中央 `assets/icons/splash_icon.svg`（直接复制 Web 端 splash-icon.svg，flutter_svg 渲染，96px 上移 40px），splash-icon-in 0.7s scale 0.72→1；底部 text-3xl 流光 GradientLogo + 「静夜思云提供计算服务」（延迟 0.45s 渐现）；3000ms 停留 + 400ms 淡出。
  3. 协议文案：`scripts/convert_agreements.py` 机械转换 `frontend/src/data/agreements.ts` → `core/data/agreements.dart`（user 16 章 89 段 / trans 16 章 79 段 / privacy 12 章 50 段，逐字符保真，禁止手改）；AgreementViewer 重构为全屏右滑页（顶栏 BackIcon+下载、中央流光 Logo、修订/生效时间、正文《…》链接互跳、footer 联系方式）。
  4. 同步对齐返工：CapsuleInput 去图标/密文切换、LoginMethodSheet 改 rounded-2xl 边框卡片行、登录页/注册页布局与文案逐行对齐 TSX（「{n}s 重新获取验证码」「我已阅读并遵守…继续使用」等）。
- **教训**：凡「100% 还原」条目，编码前必须先读对应 TSX/CSS 源文件，禁止凭记忆或近似实现。

## 瓶颈 11：staging release 包体积虚增 450MB（AGP strip 任务对预编译引擎不生效）

- **时间**：2026-10-11
- **现象**：assembleStagingRelease 产出 499MB，解包发现 libflutter.so（release 引擎）三个 ABI 各 150-165MB。
- **根因**：Flutter 官方预编译引擎 AAR 内的 libflutter.so 携带完整 DWARF 调试段；AGP 的 StripDebugSymbols 任务未对其执行剥离（任务 UP-TO-DATE 且输出未变），手动 llvm-strip 可降至 8-12MB/ABI。
- **连带问题**：首次 R8 构建失败（Play Core 缺类告警），已补 `-dontwarn com.google.android.play.core.**`；staging/prod release 缺签名配置会产出 unsigned 不可安装包，已在 :app 增加 signingConfigs（凭据从 local.properties 读取，keystore 不入库）。
- **方案**：:app 构建脚本对所有 `strip*DebugSymbols` 任务追加 doLast，用 NDK llvm-strip 处理 >32MB 的 so；处理后 staging release 从 499MB 降至 50MB。
- **附带**：`flutter build aar` 三变体全量构建在沙箱内耗时过长且后台进程易被回收，本轮未采用；module 模式 + 手动 strip 已满足发布体积要求，AAR 模式留作 CI 方案。


## 瓶颈 12：Flutter 入口未接入 + 启动交接断裂（用户验收发现）

**现象**：安装 r1 包后，①开屏 Porten 文本 Logo 无流光动画；②开屏 3s 后进入原生「移动端骨架已就绪」占位页，而非登录界面。

**根因**：
1. `flutter/porten_flutter/lib/main.dart` 仍是模板计数器 Demo，从未调用 `bootstrap.dart` 的 `runPortenFlutterApp()`——即使引擎预热成功，Dart 侧跑的也不是 PortenApp。
2. `FlutterHost.warmUp()` 全工程无任何调用点，缓存引擎永远为空。
3. `PortenLauncherHost` 的 `Ready` 分支硬编码 `SkeletonPlaceholder()`，与 Flutter 侧无交接设计。

**修复**：
- `main.dart` 改为 `void main() => runPortenFlutterApp();`（DartEntrypoint.createDefault 默认入口即 main）。
- `MainActivity.onCreate` 中调用 `FlutterHost.warmUp(this)`（幂等），开屏 3s 与 Dart 初始化并行。
- 新增 `:feature:hybrid` 的 `FlutterContainer` Composable（AndroidView + FlutterView.attachToFlutterEngine，单缓存引擎模式）。
- `PortenLauncherHost` 增加 `readyContent` 参数，由 :app 注入 `FlutterContainer`，开屏结束直接呈现 Flutter 登录界面。
- 流光动画对齐 Web CSS：文本 Logo 16s linear 往返（0%→100%→0%）；按钮 8s ease-in-out 往返；协议点 135deg 渐变平移 3s ease-in-out 往返。全部改为 `repeat(reverse: true) + Curves`（或线性 pingpong 映射），禁止单向 sweep 近似。

**验证**：`flutter analyze` 0 issues；`./gradlew clean assembleStagingRelease` 成功，产物 56MB（`Porten-staging-release-1.0.0-20261011-r2.apk`）。

**遗留**：资产目录旧 APK（debug 707MB 残件、r1 包）在服务端已不存在（删除接口返回 not found），无需人工清理；新包以 r2 命名避免同名混淆。
