# Porten 移动端（Android + Flutter 混合）骨架接手文档

> 适用范围：`Porten/mobile/` 目录。只写技术架构、项目风格、代码风格、命名规范、项目规范。

## 一、技术架构

### 1. 总体形态

- **Add-to-App 混合开发**：Android 原生壳 + Flutter Module（`flutter/porten_flutter`）。
- **职责分工**（架构第一原则）：
  - Android 原生：核心能力——长连接保活（IM）、通信（HTTP/WS）、推送、安全存储、运行时防护；
  - Flutter：表现层——UI、消息渲染等非核心部分；
  - 数据单向流动：Flutter 只通过桥接（MethodChannel）消费原生能力，禁止直接访问网络/存储。
- **H5 扩展**：`core:webview` 提供白名单加固 WebView 容器，预留 H5 混合页面装载。
- **iOS 预留**：core:model 为纯 Kotlin、core:design 令牌为三方一致数据源，均为跨端复用预留。

### 3. 模块结构（settings.gradle.kts 全量声明）

```
mobile/
├── app/                    # 宿主壳：Application/Activity/flavor/签名，禁止业务逻辑
├── build-logic/            # 约定插件（Included Build）：6 个 porten.* 插件
├── core/
│   ├── model/              # 纯 Kotlin 数据模型（kotlinx.serialization，可桥接传输）
│   ├── common/             # AppResult / CrashGuard / AppLogger / DispatchersProvider
│   ├── design/             # 设计令牌（Kotlin 侧）：颜色/字阶/间距/缩放
│   ├── security/           # 运行时防护：root/调试/模拟器检测
│   ├── storage/            # Keystore 加密存储（EncryptedSharedPreferences）
│   ├── network/            # OkHttp 统一出口（明文拦截/敏感日志脱敏）
│   ├── im/                 # 长连接状态机：心跳/指数退避重连/消息流
│   ├── push/               # 推送统一收件柜（多厂商 Provider 模式）
│   ├── bridge/             # 原生↔Flutter 通道契约（依赖倒置，不依赖 Flutter SDK）
│   ├── webview/            # H5 白名单加固容器
│   ├── data/               # Repository：Mock/Live 双通道分发
│   └── ui/                 # 原生 Compose 组件库（缩放密度/禁水波纹主题）
├── feature/
│   ├── launcher/           # 启动编排：Splash 状态机（3000ms，对齐 Web）
│   ├── main/               # 主容器（底部导航）
│   └── hybrid/             # 唯一依赖 :flutter 的模块：引擎预热/通道装配
└── flutter/porten_flutter/ # Flutter Module（Riverpod 状态管理）
```

- **依赖边界**：core 不得依赖 feature；feature 之间禁止横向依赖；feature:hybrid 是唯一可依赖 `:flutter` 的模块。
- **依赖注入**：骨架阶段未引入 DI 框架（KSP 与 Kotlin 2.2.x 尚无配套版本），以约定插件 + 手工装配为主。

### 4. Flutter 集成双模式

- `gradle.properties` → `porten.flutter.mode = module | aar`：
  - **module**（开发期）：源码依赖 `:flutter`，支持源码级断点；
  - **aar**（发布期）：依赖 `flutter build aar` 产出的本地 Maven 产物。
- 切换无需改任何模块代码。

### 5. 环境与 Mock 切换（对齐 Web 端 VITE_USE_MOCK）

- flavor `environment = dev | staging | prod`，每个 flavor 注入 `API_BASE_URL / API_WS_URL / USE_MOCK / ENABLE_SECURITY / ENABLE_LOGGING`；
- `porten.mock.enabled` gradle 属性可在命令行 `-P` 覆盖；**prod 强制 USE_MOCK=false**；
- Flutter 侧 Mock 引擎（`lib/core/mock/`）：模式由原生 env 桥注入，handler 注册表 + 确定性随机 + 延迟模拟。

### 6. 安全基座

- 构建期：`porten.release.hardening` 约定插件（R8 full mode + minify + shrinkResources）、`proguard-rules.pro`（Log 移除/模型保留/Flutter JNI 保留）；
- 网络层：TLS-only + 证书绑定占位（`network_security_config.xml`，pin 待真实域名）；
- 数据层：`allowBackup=false`、`dataExtractionRules` 禁云备份与设备迁移、`dependenciesInfo` 不写入 APK；
- 运行期：`SecurityGuard`（root/调试/模拟器检测）由 `SecurityStartupTask` 在启动最早期执行，dev flavor 整体跳过；
- 存储：Keystore AES256-GCM 加密 KV，初始化失败降级为纯内存（绝不明文落盘）。

## 二、设计还原体系（100% 对齐 Web 端）

- **单一数据源**：`design/tokens/porten_design_tokens_v1.json`；
- **三方一致**：JSON ↔ Kotlin（core/design/tokens）↔ Dart（lib/core/design），由 `scripts/verify_design_tokens.py` 强制校验（改任何一侧必须同步并跑校验）；
- **等比缩放**：width-first 策略，基准 375dp，缩放系数 clamp 到 [0.8, 1.35]；文字不随宽度缩放（跟随系统字体设置，上限 1.3）；
- **交互还原**：全局禁用水波纹——原生侧 `LocalRippleConfiguration provides null`，Flutter 侧 `NoSplash.splashFactory` + 透明 splash/highlight；按压反馈用自定义透明度/缩放（`PortenPressFeedback`）。

## 三、代码风格与命名规范

- **Kotlin**：官方代码风格（`kotlin.code.style=official`）；顶层常量 PascalCase（`SpaceXL`、`RadiusPill`）；公开 API 显式 `public`；模块内可见用 `internal`；注释为中文 KDoc，说明「职责边界 + 数据来源 + 约束原因」。
- **Dart**：Effective Dart；常量 lowerCamelCase（`spaceXL`、`radiusPill`）；`abstract final class` 承载令牌；与 Kotlin 侧同名令牌一一映射（映射关系写在文件头注释）。
- **资源命名**：`porten_` 前缀（非 transitive R class 下跨模块资源需完全限定名）。
- **包结构**：`jys.porten.<layer>.<domain>`；feature 模块内按 ui / viewmodel / model / navigation 子包拆分。
- **文件头注释**：每个文件头必须有块注释说明职责边界（本工程统一风格）。

## 四、构建与验证

```bash
cd mobile
./gradlew assembleDevDebug        # 首次构建已验证通过（379 tasks）
./gradlew assemble{Dev,Staging,Prod}{Debug,Release}
python3 scripts/verify_design_tokens.py   # 设计令牌三方一致性校验
flutter analyze                   # Flutter 静态检查（当前 0 issues）
```

- `local.properties` 不入库（sdk.dir / flutter.sdk），新环境需按模板补齐；
- `gradlew` 分发地址指向腾讯镜像（弱网环境稳定性已验证）。
