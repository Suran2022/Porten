# Porten 项目接手文档

> 本文档面向新接手开发者，帮助快速理解项目用途、技术与架构，并系统说明项目的**项目结构风格、代码风格、命名规范、代码规范**，以便保持风格统一。

---

## 一、项目用途

**Porten** 是一个面向跨性别群体打造的温暖通信与社区平台，核心诉求是**安全、包容、连接、治愈**。

主要功能模块：

- **即时通信**：单聊、群聊，支持文本 / 图片 / 视频 / 语音 / 文件等多种消息类型；WebSocket 实时推送、离线消息同步；媒体永久保存。
- **情绪日记**：每日心情记录、多维度情绪标签、可见性管理、历史回顾。
- **同胞社区**：同胞资料页、音乐分享、系统通知、资源中心（医疗 / 组织 / 流程指引）。
- **账号与安全**：邮箱验证码登录 / 密码登录 / Porten ID 登录、邮箱更换、协议体系。

- **React 18** + **TypeScript**（Hooks + 函数组件）
- **Vite 6** 构建，`@` 别名指向 `src`

- **SQLAlchemy 2.0** 声明式映射（`Mapped` / `mapped_column`）
- **Alembic** 数据库迁移

## 三、整体架构

前后端分离的 C/S 架构，通过 HTTP + WebSocket 通信：

```
Frontend (React/Vite, :3002)  ──HTTP /api/v1──▶ Backend (FastAPI, :8000)
        │                            ──WS /ws──▶        │
        │                                                ├── Routers  (路由层)
        │                                                ├── Services (业务层)
        │                                                ├── Models   (ORM)
        │                                                └── MySQL / 文件上传目录 /uploads
```

- 开发期前端通过 Vite `proxy` 将 `/api/v1` 与 `/ws` 转发到后端（见 `frontend/vite.config.ts`）。
- 后端所有响应统一包一层 `ResponseModel{code, message, data}`，异常由全局异常处理器统一转换。
- 前端内置 **Mock 模式**：`src/lib/mockMode.ts` 的 `USE_MOCK` 开关，为 `true` 时所有请求由 `mockEngine` 接管，可绕过后端独立演示/联调。
- 媒体文件经 `/upload` 上传后由后端 `StaticFiles` 服务，路径挂载在 `/uploads`。

## 四、项目结构风格

### 后端分层（`backend/app/`）

按**职责分层**组织，每层一个目录，同层只做一种事：

```
app/
├── migrations/         # Alembic 迁移（versions/ 自 0001 递增）
├── models/             # ORM 模型（一文件一实体）+ base.py（Base/TimestampMixin/utc_now）
├── routers/            # API 路由（一资源一文件，只做参数收口与编排）
├── schemas/            # Pydantic 请求/响应模型（与 models 同名对应）
├── services/           # 业务逻辑服务（一领域一 Service 类）
├── dependencies/       # FastAPI 依赖注入（如 get_current_user）
├── utils/              # 通用工具（security / validators）
├── config.py           # Settings 配置加载（get_settings() 单例缓存）
├── database.py         # engine / SessionLocal / get_db()
└── main.py             # 应用入口：建表、路由注册、异常处理、CORS、静态挂载
```

**层级调用方向**：`routers → services → models`；`schemas` 在 router 与 service 之间传递；`dependencies` 供 router 使用公共鉴权；`utils` 为纯函数工具。

### 前端分层（`frontend/src/`）

按**目录分工**组织：

```
src/
├── components/     # 业务组件（按触点再分 home/profile/knowledge/resource/desktop/music/common）
├── pages/          # 页面级组件（路由挂载点）
├── store/          # Zustand 状态（auth/chat/message/contact/systemMessage/toast）
├── hooks/          # 自定义 Hooks（useXxx，含移动/桌面交互与录音/主题）
├── lib/            # API 封装、缓存、工具、Mock 引擎
├── types/          # TS 类型定义（按领域 chat/message/partner/resource...）
├── data/           # 静态/演示数据（xxMock.ts）
├── App.tsx         # 路由与全局 Provider
├── main.tsx        # 入口
└── index.css       # 全局样式
```

- **跨层引用**：组件不直接 `fetch`，统一经 `lib/api.ts` 的函数；全局状态只放 Zustand store。
- **别名**：`@/*` 映射到 `src/*`。
- **类型与数据**：接口类型集中在 `lib/api.ts` 内（与后端字段 snake_case 对应）及 `types/` 下按领域拆分。

## 五、代码风格

### 后端（Python）

1. **模块 docstring**：每个 `.py` 文件第一行用英文三引号说明用途，如 `"""User model."""`、`"""Authentication routers."""`。
2. **函数/类 docstring**：每个类、每个非平凡方法都有英文 docstring，说明"做什么"；含校验逻辑时用 `Raises:` 标注异常。
3. **空行**：import、模块级常量/实例、类定义、函数之间用单空行分隔，保持 PEP8 风格；类内方法之间空一行。
4. **类型注解**：广泛使用现代注解——模型用 `Mapped[T]` / `mapped_column`，函数参数与返回值标注类型，`Optional[T]` 表示可空。
5. **枚举**：字符串枚举用 `class X(str, PyEnum)`，值为小写 snake_case（如 `UserRole.USER = "user"`），并以模块级集合/映射常量补充（如 `CIS_GENDERS`、`MOOD_LABELS`）。
6. **SQLAlchemy 模型**：
   - 继承 `Base`，时间戳字段用 `TimestampMixin`，默认时间用 `utc_now()`（UTC）。
   - 每列用 `comment=` 说明业务含义；主键统一 `BigInteger` 自增。
   - 关联用 `relationship(...)`，`lazy="selectin"`，级联 `cascade="all, delete-orphan"`。
   - 表名复数（`users`/`messages`），模型文件用单数（`user.py`）。
7. **统一响应**：路由一律 `return ResponseModel(data=...)`；参数校验用 Pydantic `Field` / `field_validator`；业务异常在 service 抛 `ValueError`，router `raise HTTPException(...) from exc`。
8. **service 实例化**：模块级创建单例（如 `user_service = UserService()`）。
9. **配置访问**：通过 `get_settings()`（`lru_cache` 缓存）读取常量，不使用散落的字面量。

### 前端（TypeScript/React）

1. **单文件单默认导出组件**为主；命名导出用小写 `cn` 工具等。
2. **React 组件**为函数组件 + Hooks，`useEffect` 清理副作用（`return () => clearTimeout(...)`）。
3. **样式**：优先 Tailwind 原子类；多条件合并用 `cn(...)`（`clsx` + `tailwind-merge`）；自定义变量/过渡用行内 `style`。
4. **状态**：用 Zustand `create<State>()((set, get) => ({...}))`；`set` 更新、`get` 读取当前 state。
5. **API 封装**：所有请求走 `lib/api.ts` 的统一 `apiRequest<T>`，自动附带 `Authorization: Bearer <token>`，返回 `result.data`，错误统一抛 `ApiError`/`TimeoutError`。
6. **时间处理**：统一在 `lib/utils.ts` 提供 `formatMessageTime` 等工具，业务组件不重复写时间逻辑。
7. **注释**：前端注释中英文混用，较多中文注释说明业务意图（如"Mock 模式下……"、"桌面端使用分栏版认证页"）。
8. **Mock 与真实模式共存**：业务代码不硬编码 mock，通过 `USE_MOCK`/`mockEngine` 切换（见约束）。

## 六、命名规范

### 后端（Python）
| 对象 | 规范 | 示例 |
|------|------|------|
| 模块/文件 | snake_case，一实体一文件，单数 | `user.py`、`message.py` |
| 类/枚举 | PascalCase | `UserService`、`UserRole`、`EmotionDiaryView` |
| 函数/方法 | snake_case | `get_current_user`、`build_login_response` |
| Service 类 | `<领域>Service` | `UserService`、`EmailService` |
| Router 实例 | 模块内以 `<资源>_router` 导出，带前缀 | `router = APIRouter(prefix="/api/v1/auth")` |
| 数据库表 | 复数 snake_case | `users`、`emotion_diaries` |
| 列/约束 | snake_case；唯一约束前缀 `uq_` | `uq_emotion_diary_view` |
| 外键 | `<目标>_id` | `user_id`、`diary_id` |

### 前端（TypeScript/React）
| 对象 | 规范 | 示例 |
|------|------|------|
| 组件文件 | PascalCase `.tsx` | `AuthSlider.tsx`、`ChatPage.tsx` |
| 组件名/导出 | PascalCase（默认导出为主） | `function ChatPage()` |
| 普通函数/方法 | camelCase | `formatMessageTime` |
| Hooks | `use` + camelCase 前缀 | `useIsDesktop`、`useTheme` |
| Zustand store | `useXxxStore` | `useAuthStore`、`useChatStore` |
| 接口类型 | PascalCase，`XxxData`/`XxxItem`/`XxxResult` 后缀 | `LoginData`、`MessageItem`、`ProfileData` |
| 类型文件 | 领域名单数/复数均可，语义清晰 | `chat.ts`、`emotionDiary.ts` |
| 枚举似联合 | 常量用 UPPER_SNAKE | `API_BASE_URL`、`TOKEN_KEY` |
| 接口字段 | 与后端 snake_case 一致（如 `avatar_url`），转驼峰在 store 映射层完成 | `mapLoginData` |

> **关键约定**：前端与后端交互字段保持后端 snake_case（`porten_id`、`avatar_url`）；前端组件内部状态/Props 用 camelCase。二者在 store 的映射函数（如 `mapLoginData`）处转换。

## 七、代码规范（工程约束）

### 后端
- **依赖管理**：`requirements.txt` 固定主版本（如 `fastapi==0.111.0`），无锁文件。
- **数据库变更**：一律通过 Alembic 迁移（`alembic upgrade head`），新 migration 序号续接。
- **统一响应协议**：所有接口返回 `ResponseModel{code,message,data}`；鉴权失败返回 `401`；业务错误由 `HTTPException` 携带国际化小写英文 `detail`。
- **JWT 会话控制**：`access_token_expire_minutes` 可控；`token_version` 递增实现登出失效，鉴权依赖 `get_current_user`（`dependencies/auth.py`）。
- **流式依赖**：数据库会话通过 `Depends(get_db)` 注入，方法内结束时由 provider 关闭。
- **测试**：`backend/tests/` 使用 pytest（含 pytest-asyncio）；启动/迁移相关测试见 `test_smoke.py`。
- **安全**：密码 bcrypt（rounds=12），JWT 用 `HS256`，敏感配置从环境变量读取。

### 前端
- **构建**：`npm run dev`（端口 3002）、`npm run build`（`tsc -b && vite build`，产物在 `dist/`）、`npm run lint`（eslint）、`npm run check`（类型检查）。
- **Lint/格式化**：ESLint 基于 `js.configs.recommended` + `typescript-eslint` + react-hooks/recommended + react-refresh（组件外常量导出仅 `allowConstantExport`）；忽略 `dist`。
- **TS 约束**：`tsconfig.json` 中 `strict: false`、`noUnusedLocals/noUnusedParameters: false`，`@/*` 路径别名。
- **代码分割**：`vite.config.ts` 用 `manualChunks` 拆 `react-vendor/state/icons/pdf`；`sourcemap: 'hidden'`。
- **环境变量**：`.env` 提供 `VITE_API_BASE_URL`、`VITE_API_WS_URL`；API 默认回退到 `http://localhost:8000/api/v1`。
- **状态流转**：认证状态统一在 `authStore`；消息与会话状态分别在各 store，不跨页直接改全局。
- **Mock 一致性**：`data/*Mock.ts` 与 `mockEngine` 需与真实后端字段保持一致，避免切换 Mock 时字段错位。

## 八、快速上手参考命令

```bash
# 后端
cd backend
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # 配置 DATABASE_URL/SECRET_KEY/SMTP
alembic upgrade head
uvicorn app.main:app --reload --port 8000   # API 文档 http://localhost:8000/docs

# 前端
cd frontend
npm install
npm run dev                     # http://localhost:3002

# 无需完整后端时可开启 Mock：在 src/lib/mockMode.ts 将 USE_MOCK 置 true
```
